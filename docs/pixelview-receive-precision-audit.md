# Receive precision audit (nonshipping experiment)

## Outcome

Current reception is **not 10-bit end-to-end**. A narrow receive adapter plus a high-precision SDR canvas can preserve more than eight bits up to the main GPU texture without selecting HDR. Fullscreen and native SDR DeckLink remain separate eight-bit boundaries in this checkout. No production file, app settings, global configuration, hardware/capture source, credential, or staging target was changed for this audit.

Real existing-libobs/OpenGL execution on Apple M1 Pro/macOS 26.6.2:

| Async synthetic input | Canvas output configuration | Distinct red values in main texture, first 877 pixels |
|---|---|---:|
| P010 limited Rec.709 SDR | NV12 / Rec.709 / partial | 256 |
| P010 limited Rec.709 SDR | P010 / Rec.709 / partial | 877 |
| I210 limited Rec.709 SDR | NV12 / Rec.709 / partial | 256 |
| I210 limited Rec.709 SDR | P010 / Rec.709 / partial | 877 |

Run `python3 test/pixelview/run_receive_precision_probe.py`. It compiles a standalone Objective-C++ harness against existing `build_macos` libobs and loads existing OpenGL, with temporary HOME/CFFIXED_USER_HOME. It supplies codes 64..940 with neutral chroma through real `obs_source_output_video2`, then uses a real main-rendered callback and staging surface to count red-channel values. No GStreamer decoder or production receive callback is exercised by this harness. All four processes exited 0, with over 100 readbacks each. Benign hotkey-permission and deprecated data-path API warnings occurred. This measures distinct values, **not** exact code roundtrip, colorimetric accuracy, calibrated display output, chroma siting, HDR correctness, or SDI transmission.

## Actual path and boundaries

1. **Decoded GStreamer frames → adapter** (`plugins/pixelview-whep/pixelview-whep.c:107–129,192`): graph explicitly requests `videoconvert ! video/x-raw,format=BGRA`; callback only maps plane 0 into `VIDEO_FORMAT_BGRA`, sets full-range true, and calls the old output API. The graph discards ten-bit precision before libobs. BGRA full-range can be appropriate after a correct limited-YUV→full-RGB conversion; merely removing `full_range=true` is not the fix. No source caps matrix/primaries/transfer survive as OBS frame metadata. Decoder bit depth/profile capability is not receive fidelity.
2. **Async raw formats** (`libobs/obs-source.c:1723–1789,2230–2374`, `obs-internal.h:1074–1120`): P010, I010, I210, V210, R10L have actual reverse conversion paths. I210 is planar little-endian 10-bit 4:2:2; I010 planar low-aligned 10-bit 4:2:0; P010 uses high-aligned words. Their names are not interchangeable. P216/P416 exist in enums and output GPU conversion but async source reverse conversion is explicitly **Unimplemented**. Do not map incoming P210/P216 to OBS P216 just because an encoder uses it. Request I422_10LE→I210 instead for supported 4:2:2 reception.
3. **Raw upload → linear RGB texture** (`libobs/data/format_conversion.effect:686–718,852–925`): I210 normalizes 16-bit storage by 65535/1023, uses matrix YUV→RGB, then sRGB inverse transfer. P010 recovers code words by flooring away six low bits, normalizes by 1023, and uses the same SDR inverse transfer. PQ/HLG paths apply their transfer and Rec.2020→Rec.709 linear-gamut conversion; PQ also uses `st2084_to_linear_eetf`, not untouched HDR passthrough. Chroma samples use the shader's sampler/normalized coordinates; P010 rounds interpolated chroma back to 10-bit after sampling. No per-frame arbitrary chroma-siting field exists in `obs_source_frame2`; require edge/siting tests. Converting 4:2:2 to P010 in GStreamer would irreversibly remove vertical chroma detail.
4. **Source → main canvas** (`libobs/obs.c:352–435`): source precision is insufficient. NV12 output configuration selects a BGRA8 main texture. P010 or P216 output configuration selects RGBA16F and SDR `GS_CS_SRGB_16F` while **colorspace can remain Rec.709**. The experiment directly confirms this hidden boundary. P010 *output* does not turn the main RGB texture into subsampled YUV: native DeckLink consumes `obs_get_main_texture()` before encoder YUV conversion. The separate P010 raw video output is 4:2:0; use P216 output when a real 4:2:2 raw/encoder consumer requires it, with separate validation.
5. **Frontend canvas configuration** (`frontend/widgets/OBSBasic.cpp:2170–2224`): reads Video/ColorFormat, ColorSpace, ColorRange and configured render module; GPU conversion true. Default ColorFormat is NV12 (`:881`). Receive is not inherently independent of sender encoding preferences. Do not silently change a running shared pipeline; implement an explicit guarded receive precision policy, restore sender settings on exit, and distinguish in-memory pipeline choice from persisted profile changes. This audit did not read or modify the user's profile.
6. **Preview/fullscreen** (`frontend/widgets/OBSProjector.cpp:209`, `OBSQTDisplay.cpp:150`, `libobs-opengl/gl-cocoa.m:44–47,120–122,226–228`): projector uses main texture but Qt display requests GS_BGRA, Cocoa allocates that backing texture, requests no explicit 10-bit pixel format, and sets window color space to sRGB. An XDR panel does not remove this eight-bit intermediate or establish HDR/EDR output. Fixing this is a separate renderer/presentation project, not a receiver format flag. OpenGL initialization reports Metal in Apple's driver version string; that does not mean the OBS Metal backend is being used.
7. **Native DeckLink UI bridge** (`plugins/decklink-output-ui/decklink-ui-main.cpp:84–128,183–227`): always allocates BGRA stages/queue. SDR `DrawAlphaDivide` converts to ordinary eight-bit output. HDR selects `DrawAlphaDivideR10L` only when the canvas is PQ/HLG and output conversion allows PQ. **BGRA allocation does not mean HDR truncates to eight bits:** `libobs/data/default.effect:48–59` deliberately packs 30 bits into four byte channels after Rec.709→Rec.2020 and PQ, using legal codes 64..940. Blending and framebuffer-sRGB are disabled for packing. Treat those BGRA-marked bytes as a private packed payload; generic color transforms/rescaling would corrupt them.
8. **Native DeckLink device** (`plugins/decklink/decklink-output.cpp:34–42`, `decklink-device-instance.cpp:586–617`): matching gate chooses `bmdFormat10BitRGBXLE` only for HDR; SDR uses `bmdFormat8BitBGRA`. Four-byte row storage/copies serve both. RGB10 is not evidence of 10-bit YUV 4:2:2 on SDI; mode/device/link conversion requires hardware testing. `OBSVideoFrame.cpp:130–201` emits fixed PQ/Rec.2020 metadata and nominal OBS luminance, not original source mastering/CLL metadata. Force SDR means SDR output/tone mapping of HDR canvas, not preservation of ten-bit SDR.

## Color fidelity: bit depth is not dynamic range

Ten-bit SDR Rec.709 and ten-bit HDR PQ/HLG are different signals. Bit depth counts quantization levels; matrix, range, primaries and transfer describe their meaning. Never infer PQ from HEVC Main10/Main42210 or VP9 profile 2/3, nor use HDR mode solely to obtain RGB10 output.

Map **negotiated decoded caps**, not compressed profile names: format, plane count, actual strides, endian/bit alignment, matrix, quantization range, transfer, primaries and chroma site. Limited ten-bit luma nominal black/white 64/940 differs from full 0/1023; chroma nominal center 512 and legal bounds need format-aware parameters. Call `video_format_get_parameters_for_format`, check its result, populate range/matrix/min/max and use `obs_source_output_video2`. Preserve copy-before-unmap lifetime and generation/delivery lock logic. Reject unsupported layouts and negative/out-of-bounds strides rather than interpreting their memory incorrectly.

`video_trc` only exposes DEFAULT/SRGB/PQ/HLG (`libobs/media-io/video-io.h:99–113`); there is no exact general BT.709/BT.1886/log transfer or independent arbitrary-primary descriptor. The SDR shader's sRGB inverse is an actual processing decision, not a grading guarantee. PQ/HLG shader gamut handling assumes Rec.2020. Unknown colorimetry needs an explicit documented fallback/status, not silent HDR guessing; non-709 SDR gamut/log material needs an intentional transform or refusal. Preserve decoder-side HDR metadata for telemetry if supported, but current frame2/native DeckLink cannot simply forward all original mastering metadata.

## Recommended narrow production patch (not applied)

**Stage A: remove avoidable receive loss without promising physical 10-bit output.**

- Negotiate supported raw formats without unconditional BGRA8: retain native NV12/I420 for ordinary eight-bit input, P010_10LE or I420_10LE for ten-bit 4:2:0, and I422_10LE for ten-bit 4:2:2; keep an explicit compatible RGB fallback. A caps list can still choose an undesired format: assert negotiated format/depth/chroma and prefer passthrough before conversion.
- Implement one table-driven caps→OBS frame2 adapter with format-aware matrix/range and validated plane strides; validate supported SDR/HDR colorimetry independently of depth. Do not advertise P216 async support.
- Expose negotiated safe diagnostics (depth, chroma, matrix/range/transfer and fidelity limitations), without URLs/tokens.
- Separately select a guarded high-precision receive canvas (P010 + Rec.709 for SDR; HDR only for actual supported HDR intent). This must be coordinated with native outputs/encoder activity and preserve prior sender configuration. Adapter-only change retains precision in the source but still loses it on an NV12 canvas.

**Stage B: optional ten-bit SDR DeckLink, separate scoped change.**

Reuse existing byte-packing transport but separate `high_bit_depth` from `hdr`: add an SDR RGB10 packing technique (no PQ/gamut conversion or tone map), select compatible `bmdFormat10BitRGBXLE` independently of HDR, and wrap HDR metadata only for true HDR. Keep shader and device decisions driven by one explicit output policy, validate actual device/mode support, and fail with a truthful unsupported-mode error instead of silently reverting to eight-bit. Full-range/limited RGB10 convention and SDI conversion must be verified with hardware. Do not reuse current DrawAlphaDivideR10L unchanged: it explicitly writes PQ. A proper v210/10-bit YUV option is larger because current rows/copies assume width*4, and requires siting, row-padding, pixel-format and mode work.

## Acceptance gates before any fidelity claim

- Actual decoder→production callback fixtures for HEVC Main/Main10/Main42210 and VP9 supported profiles: negotiated bit depth/chroma, stride/padding and endian fixtures, full/limited range, Rec.601/709 and supported Rec.2020 PQ/HLG. Unsupported combinations fail truthfully; eight-bit must not gain a misleading ten-bit label by upconversion.
- Adjacent-code ramps at callback and main texture: require all 877 neutral legal-range input levels for the tested SDR path, monotonicity, endpoint accuracy against a defined reference, and quantitative tolerances. Include near-black, superblack/superwhite clipping policy, chroma impulses/checkerboards, saturated patches and resize/filter tests. The current probe only counts levels and cannot replace these tests.
- Regression for source→NV12 canvas intentionally demonstrates 256 levels, while high-precision SDR stays SDR and exceeds eight-bit precision. Check caps renegotiation, generation cancellation, disconnect/reconnect and source changes without stale matrices/planes.
- Real DeckLink packed-byte roundtrip tests before hardware; for physical claims, actual selected mode, wire pixel format/range/transfer metadata and independently captured ramp/code-value measurements, cadence and long A/V sync. Distinguish SDR RGB10 from HDR RGB10 and from 4:2:2 YUV10. Test Force SDR intentionally, including HDR tone mapping.
- Fullscreen claims require actual backing/swapchain precision, macOS color-management/EDR behavior and measured reference display output; screenshots/format names/panel marketing are insufficient.
